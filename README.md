# Практическая работа № 3 — вариант 96

Менеджер зависимостей задач. Индивидуальная работа; один продукт, подходы TDD, ATDD, BDD и SDD (Specification by Example).

## Запуск

Проверено: Python 3.12.14. Рекомендуется Python 3.12. Все команды выполняются из каталога `code`.

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py --demo
python app.py
```

Самому приложению нужны только стандартные библиотеки Python. Пакеты из requirements.txt используются для проверок.

## Проверки

```sh
python run_checks.py --stage final
python check_console.py
# Воспроизведение сохранённых этапов:
python run_checks.py --stage all
# Отдельные инструменты на итоговом модуле:
python -m pytest
python -m behave features
```

Итог: TDD 30 passed, ATDD 5 passed, SDD 10 passed; Behave 6 сценариев, 22 шага passed. Дополнительно 3 проверки реального консольного процесса. Покрытие только task_manager.py при запуске pytest: 80/80 строк и 28/28 ветвей.

На RED ожидаются 45 failed pytest и 6 сценариев Behave со статусом error из-за NotImplementedError. Это намеренные заглушки. Управляющий run_checks.py считает ожидаемый RED успешным воспроизведением этапа, но останавливается при неожиданном результате. В GREEN и final все проверки должны проходить. Повторные запуски перезаписывают результаты соответствующего этапа.

## Файлы

- `task_manager.py`: итоговый модуль, алгоритм Кана, валидация, расписание.
- `app.py`: меню и `--demo`.
- `implementation.py`: загрузка модуля из пути TASK_MANAGER_IMPL (для тестов этапов).
- `tests/conftest.py`: новый менеджер для каждого теста.
- `tests/test_tdd.py`, `tests/test_atdd.py`, `tests/test_sdd.py`: отдельные наборы.
- `features/planning.feature`: русские сценарии Gherkin.
- `features/environment.py`, `features/steps/planning_steps.py`: окружение и автоматизация шагов.
- `specifications/examples.csv`: десять исполняемых примеров. JSON-поля содержат задачи [ID, длительность], связи [зависимая, предшественник], расписание [ID, начало, конец].
- `stages/red/task_manager.py`: интерфейс с заглушками.
- `stages/green/task_manager.py`: первая работающая версия до рефакторинга.
- `run_checks.py`: запуск этапов, проверка кодов завершения, протоколы и покрытие.
- `check_console.py`: три проверки консоли.
- `results/{red,green,final}`: логи, XML, JSON, summary.json; в final дополнительно demo.log, консольные протоколы и coverage_html/index.html.
- `.coveragerc`: область покрытия (ядро, без сохранённых этапов).
- `pytest.ini`, `requirements.txt`: конфигурация и версии зависимостей.

## Контракт

Время — положительные целые часы от начала проекта 0. Ресурсы не ограничены: независимые задачи параллельны. Ребро A → B означает, что B ждёт A; API: `add_dependency("B", "A")`. Неизвестные вершины, самозависимость и циклы отклоняются. Повтор связи ничего не меняет. Сначала проверяется копия графа, поэтому отказ сохраняет прежнее состояние.

ID начинается с латинской буквы; далее буквы, цифры, `_` и `-`. ID чувствителен к регистру, уникален. Название непустое. `True`, нулевая/отрицательная или дробная длительность запрещены. Начало задачи — максимум окончаний предшественников, либо 0. Среди готовых задач для порядка вывода выбирается наименьший ID; это не запрещает параллельное начало.

Данные живут в памяти процесса. Нет сохранения, календаря, ограничений исполнителей, редактирования или удаления. Покрытие 100% не гарантирует отсутствие всех дефектов; нагрузочные и генеративные проверки не выполнялись.
